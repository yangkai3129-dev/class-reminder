# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Design authority:** The Apple Design System in `/Users/ink/.claude/CLAUDE.md` is the authoritative visual spec for this project and overrides any generic UI defaults. All color/typography/spacing/shadow/principles below are locked from it. Note: this is a Python-stdlib + plain HTML/CSS/JS browser tool (zero third-party dependencies), so this contract is written at the **CSS-token level**, not React/SwiftUI components.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no shadcn — not a React/Next/Vite project) |
| Preset | not applicable |
| Component library | none — hand-written semantic HTML + CSS |
| Icon library | none — use text labels as the primary affordance; inline SVG line icons (stroke 1.5px) only where a label is insufficient |
| Font | `-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text", "PingFang SC", "Helvetica Neue", sans-serif` |
| Corner radius | `0` on full-bleed tiles/sections; `6px` on buttons and input fields; `4px` on placeholder chips |
| Shadows | none anywhere. The single permitted shadow is reserved for product-render imagery, which this tool does not have. Visual separation is achieved by white/parchment background alternation only |

**Font-stack note (domain-necessary addition):** The tool's UI is 100% Simplified Chinese, but SF Pro carries no CJK glyphs. `PingFang SC` (Apple's Chinese system font) is inserted so Latin/digits resolve to SF Pro and Chinese resolves to PingFang SC — both zero-download system fonts, consistent with Apple's own Chinese UI.

## Spacing Scale

Declared values (multiples of 4, from the 8px base unit):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, chip internal padding |
| sm | 8px | Compact element spacing, list-row internal padding |
| md | 16px | Default element spacing, form-field gaps |
| lg | 24px | Section padding, dialog internal padding |
| xl | 32px | Layout gaps, content-area side padding |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |
| section | 80px | Top/bottom padding of a major content block (Apple's fixed section-padding rule) |

Exceptions:
- Desktop (Mac-first, mouse-driven) click targets: minimum hit area **32px** height. Primary buttons use **40px** height (8×5). No 44px touch-target requirement — this is not a touch UI.
- The left sidebar is a fixed **240px** wide rail; content area side padding is `xl` (32px).

## Typography

Font-weight ramp is locked to **300 / 400 / 600 / 700** (there is no 500). Phase 1 uses 400, 600, and 700; 300 is available but unused here.

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Label | 13px | 400 | 1.4 | Secondary text, form labels, list metadata, hints |
| Body | 17px | 400 | 1.47 | Default content, form values, list names, button text |
| Heading | 22px | 600 | 1.2 | Dialog titles, section headings, nav group labels |
| Title | 34px | 700 | 1.1 | Page-level title; `letter-spacing: -0.022em` (tight, per Apple) |

Secondary text color is `#6e6e73` (Apple secondary label); primary text is `#1d1d1f`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` | Main content background, dialogs, editors, inputs |
| Secondary (30%) | `#f5f5f7` | Sidebar rail, category tab bar, empty-state region, hover tint, template preview box |
| Accent (10%) | `#0066cc` | Interactive elements only (see reserved list below) |
| Destructive | `#ff3b30` | Delete/remove actions and their confirmation only (Apple systemRed semantic) |

Neutrals (locked to Apple HIG values):

| Token | Value | Usage |
|-------|-------|-------|
| text-primary | `#1d1d1f` | Headings, names, form values |
| text-secondary | `#6e6e73` | Labels, hints, template preview |
| divider / border | `#d2d2d7` | Input borders, list-row separators |

Accent reserved for (explicit list — never a blanket "all interactive elements"):
1. Primary CTA buttons (「新建档案」「添加教室」「保存」)
2. Text-link actions (「编辑」) and the active navigation item in the sidebar
3. Selected category tab (segmented control) indicator
4. Focus ring on any focused input/button
5. The three placeholder tokens `{时间}` `{教室号}` `{老师}` rendered as inline chips inside the template composer and any preview

Anything not in this list uses `#1d1d1f` (text) or neutral surfaces. No gradients anywhere — depth comes from white/parchment alternation, not CSS effects.

## Screen Inventory & Navigation

Single-page app. Persistent shell + two content views (Phase 1). Phase 2 (daily fill) and Phase 3 (copy) will render inside the 档案 view — the shell reserves this by making "open a profile" the primary row interaction.

**Shell (persistent)**
- Left sidebar (240px, background `#f5f5f7`): app title 「上课提醒」 at top; two nav items 「档案」「教室」.
- Active nav item: text `#0066cc` on a light `#0066cc`-tinted (≈ `rgba(0,102,204,0.08)`) selection — no heavy fill, no shadow.
- Main content area (background `#ffffff`): swaps between the two views. Content area side padding `xl` (32px), section vertical padding `section` (80px).

**View 1 — 档案 (Profiles)** *(entry point that Phase 2/3 extend)*
- Header: page title 「档案」 (34px) left; primary button 「新建档案」 (blue, 40px) right.
- List of profile rows. Each row: name (17px/600), template preview line (13px, `#6e6e73`, truncated, placeholders shown as blue chips). Row actions 「编辑」(blue link) and 「删除」(red link) on the right.
- Primary row click and 「编辑」 both open the profile editor (View 3).
- Empty state when no profiles.

**View 2 — 教室 (Rooms)**
- Header: page title 「教室」 left; primary button 「添加教室」 right.
- Segmented control with two tabs: 「班课教室」 | 「VIP教室」. Active tab text `#0066cc` with a 2px blue underline (Apple's segmented-control style); inactive tabs `#1d1d1f`.
- Room list for the active category. Each row: room number (17px) + 「编辑」「删除」 actions. Adding a room assigns it to the currently active category.
- Empty state per category.

**View 3 — 档案编辑器 (Profile editor — create & edit, modal dialog)**
- Centered modal (max-width 560px, background `#ffffff`, radius `6px`) over a dimmed backdrop `rgba(0,0,0,0.4)` (dimming, not a shadow, provides separation).
- Title: 「新建档案」 or 「编辑档案」 (22px/600).
- Field 1 — 「学生/班级名称」: text input (17px), placeholder 「例如：张三 · 海生2册」.
- Field 2 — 「提醒模板」: composer area (contenteditable, min-height 120px, white, 1px `#d2d2d7` border, `6px` radius) with three insert buttons above it (「{时间}」「{教室号}」「{老师}」). Inserted tokens render as inline blue chips. Fixed text is typed normally.
- Live preview box (background `#f5f5f7`, radius `6px`) showing the template with sample values substituted (e.g. 9:00-10:30 / 2802 / 王国香).
- Actions: 「取消」(secondary) + 「保存」(primary blue).

**View 4 — 删除确认 (Delete confirmation, modal dialog)**
- Centered modal, title 「删除档案」/「删除教室」, body the confirmation copy above, actions 「取消」(secondary) + 「删除」(destructive `#ff3b30`).

## Interaction States

| State | Behavior |
|-------|----------|
| Focus | 2px `#0066cc` ring on the focused input/button |
| Hover (primary button) | Background `#0066cc` → `#005bb5` |
| Hover (link) | Underline |
| Hover (list row) | Subtle `#f5f5f7` tint; reveals nothing hidden — actions are always visible |
| Disabled | 40% opacity, no pointer events |
| Save success | Modal closes; the list updates in place (the visible change IS the feedback — no toast needed) |
| Save failure | Inline error text under the field, or the modal stays open with the error copy above |

**Apple principles to honor throughout:** no decorative elements; at most one visual focus per screen (the primary CTA or the active editor); white space is intentional, not empty; no gradients; no shadows.
