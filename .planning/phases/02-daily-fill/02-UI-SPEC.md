Exceptions: none beyond Phase 1's existing "desktop click targets ≥32px height, primary button 40px" rule.

## Screen Inventory & Navigation

Single-page app. The Phase 1 shell (sidebar 「档案」「教室」) is unchanged. Phase 2 adds one full content-area view inside the 档案 view and changes one existing navigation behavior.

**Navigation change (must be called out in the plan):** In Phase 1, clicking a profile row's main area and 「编辑」 both opened the profile editor. In Phase 2:

- **Clicking the profile row's main area (name + template preview) opens the new fill screen (View 6).** The row gets `cursor: pointer` and the existing hover `#f5f5f7` tint; actions stay visible.
- **「编辑」 still opens the profile editor (View 4)** — unchanged.
- **「删除」 still opens the delete confirmation (View 5)** — unchanged.

**View 6 — 每日填写 (Daily fill, full content-area view)**

- Layout, top to bottom:
  1. **Header row:** back link 「‹ 档案」 left; global toggle (segmented control 「点选/滚轮」 | 「直接输入」) right.
  2. **Title:** student name (34px/700, `-0.022em`).
  3. **Field cards** (only the fields whose placeholder token is present in the student's template; at least one always appears because Phase 1 validation requires ≥1 placeholder). Order: 上课时间 → 教室号 → 老师.
  4. **Footer action row:** primary button 「确认」 (right-aligned, 40px, `.btn-primary`).
- Background `#ffffff`; side padding `xl` (32px); content scrolls vertically with the page (no sticky elements required).

**Field render rule (resolved discretion):** A field card is rendered only if its placeholder token appears in the student's template — `{时间}` shows 上课时间, `{教室号}` shows 教室号, `{老师}` shows 老师. Rationale: the three values are template placeholders; showing a picker for a token the template never uses adds noise with no function. The planner may override to "always show all three" if the colleague prefers a uniform daily routine; the control specs below are identical either way.

**Field 1 — 上课时间 (time)**

- **点选/滚轮 mode:** Apple-Event-style **double scroll wheel** — two adjacent vertical wheels (start time left, end time right), `md` (16px) gap.
  - Each wheel: 120px wide × 160px tall (5 rows × 32px), vertically scrollable, values `06:00`–`23:45` in 15-minute steps (72 values), format `H:MM` (no leading zero, e.g. `9:00`, `9:15`, `23:45`).
  - Selection band = the center row, visually delimited by a 1px `#d2d2d7` horizontal line above and below it. Selected value `17px/600 #1d1d1f`; rows above/below `13px/400 #6e6e73` (dimming with distance is optional).
  - Interaction: mouse-wheel scroll, click-drag scroll, and click-a-row-to-center all select; values snap to the 15-minute grid; range is bounded (no wrap).
  - The joined `{时间}` value = `"<start>-<end>"` (e.g. `9:00-10:30`), matching the existing `SAMPLE_VALUES` in `app.js`.
- **直接输入 mode:** two text inputs 「开始」/「结束」 (each `.input`, placeholders `9:00` / `10:30`), joined by a literal `-` between them (`sm` 8px gap). The joined value is the same `"start-end"` format.

**Field 2 — 教室号 (classroom)**

- **点选/滚轮 mode:** grouped point-select — two sub-groups with a 13px/400 `#6e6e73` group header 「班课教室」 then 「VIP教室」 (class before vip, matching the Phase 1 segmented order). Below each header, a `flex-wrap` grid of room chips (`sm` 8px gap).
  - Chip unselected: white bg, 1px `#d2d2d7` border, `6px` radius, `17px/400 #1d1d1f`, min-height 32px, padding `sm`; hover `#f5f5f7`.
  - Chip selected: `rgba(0,102,204,0.08)` bg, 1px `#0066cc` border, `17px/600 #0066cc`.
  - Single-select: tapping a chip selects it and deselects the previous; re-tapping the selected chip keeps it selected (no click-to-clear).
- **直接输入 mode:** a single `.input` text field, placeholder 「例如：2802」, free-typed room number.

**Field 3 — 老师 (teacher)**

- Always a single `.input` text field, placeholder 「例如：王国香」. **The global toggle never affects this field** (teacher is always hand-typed, per locked decision).

**Pre-fill (FILL-01):** On opening a student's fill screen, each rendered field pre-fills from the student's persisted last-used values (time start/end, room, teacher). In 点选/滚轮 mode the time wheels scroll to the stored start/end (snapping to the 15-min grid) and the stored room is shown as the selected chip; in 直接输入 mode the stored values are filled into the text inputs. If a stored room no longer exists in the room list, the classroom field falls back to unselected (no chip selected) rather than showing a stale value. First-time (no last-used value): time defaults to `9:00`–`10:30`, classroom unselected, teacher empty.

**Global toggle (FILL-04):**

- Reuses the existing `.segmented` control (17px text; active tab `#0066cc` + 2px underline; inactive `#1d1d1f`), two tabs 「点选/滚轮」 | 「直接输入」.
- **Global:** one preference for the whole tool, not per-student; persists across students and sessions. Default = 「点选/滚轮」.
- Effect: toggling swaps the time and classroom controls (wheel ⇄ inputs; chip grid ⇄ text field). The underlying current value is preserved across the swap (e.g. selected room `2802` becomes the text `2802`). The teacher field is unaffected.

**Confirm (primary CTA):** 「确认」 validates every rendered field (see error copy above), then persists the current three values as the student's last-used values and returns to the 档案 list. *(Forward note for the planner: Phase 3 will repurpose this same 「确认」 to first open the review/copy modal, then persist last-used and copy. Phase 2's confirm = validate → persist → return to list, with no copy modal.)*

## Interaction States

Phase-2-specific states (Phase 1 states — focus ring, primary-button hover, link hover, list-row hover, disabled 40% opacity — remain in force):

| State | Behavior |
|-------|----------|
| Wheel — scroll | Mouse-wheel / click-drag scrolls the column; values snap to 15-min grid; bounded (no wrap) |
| Wheel — click value | Clicking a non-center row centers (selects) it |
| Wheel — selection band | Center row `17px/600 #1d1d1f`; 1px `#d2d2d7` divider line above and below; no accent fill |
| Room chip — hover | Background `#f5f5f7` |
| Room chip — selected | `rgba(0,102,204,0.08)` bg + `#0066cc` text + 1px `#0066cc` border |
| Room chip — switch selection | Selecting a new chip deselects the previous (single-select) |
| Global toggle — switch | Swaps time + classroom controls; current value preserved across swap; teacher unaffected |
| Pre-fill | Opening a student reproduces last-used time/room/teacher; first-time falls back to time `9:00`–`10:30`, room unselected, teacher empty |
| Confirm — valid | Persists last-used values, returns to 档案 list (list refreshes; the visible change IS the feedback) |
| Confirm — invalid | Inline error text under the offending field (red `#ff3b30`, 13px/1.4); focus moves to the first invalid field; the view does NOT close |

**Apple principles to honor:** at most one visual focus per screen (the confirm CTA or the active wheel); white space is intentional; no gradients; no shadows; no decorative chrome around the pickers.

## Phase-2 Data Prerequisites (for planner awareness — behavior, not storage design)

The UI contract requires two persistence capabilities that the planner must map to the backend/data.json schema:

1. **Per-profile last-used values** — three fields (time start/end, room, teacher) reproduced on open and updated on 「确认」. The UI reads/writes these as semantic values; storage shape is the planner's decision.
